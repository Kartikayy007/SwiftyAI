# Telemetry

Telemetry records what happened during model calls, streams, tool loops, and failures.

## What it does

Telemetry primitives capture request IDs, call IDs, latency, time to first token, usage, finish reasons, errors, metadata, and tool lifecycle events where integrated.

## Why it matters

AI features need observability. You need to know which model ran, how long it took, whether it failed, and how many tokens were used.

## Before you start

1. Choose a collector for tests or app runtime.

2. Attach metadata that helps debugging.

3. Keep sensitive prompt content out of telemetry unless you explicitly need it.

## Steps

<Step title="Create a collector">
Use the built in no op or recorder style collector.
</Step>

<Step title="Attach telemetry to calls">
Pass telemetry options where supported by generation, streaming, tools, embeddings, or reranking.
</Step>

<Step title="Inspect events">
Use telemetry to debug latency, usage, failures, and tool execution.
</Step>

## Example

```swift
import Swifty_AI

let collector = TelemetryRecorder()

let response = try await generateText(
    model: model,
    prompt: "Write a changelog entry.",
    options: GenerationOptions(
        telemetry: TelemetryOptions(
            collector: collector,
            metadata: ["feature": "release_notes"]
        )
    )
)

print(response.text)
print(collector.records)
```

## API notes

OpenTelemetry export is a natural next layer. The current SDK feature focuses on public telemetry primitives and integration points.
